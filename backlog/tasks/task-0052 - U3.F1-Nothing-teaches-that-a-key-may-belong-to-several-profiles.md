> Nothing on the user-facing surface teaches that a key may deliberately belong to several profiles. `user-guide.md` documents `--add-alias` as an aliasing mechanism without connecting it to profile membership, and `edit key --add-alias`'s help text (*"create an alias for the key at `<profile>/<name>`"*) states the syntax but not the consequence. The concept is load-bearing and is only stated in `design.md`, which a user does not read.
