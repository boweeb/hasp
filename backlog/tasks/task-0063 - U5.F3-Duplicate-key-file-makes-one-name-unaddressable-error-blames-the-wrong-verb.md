Finding text, verbatim:

> A duplicated key file — which `check` itself reports as `duplicate-key-confirmed` — makes one of the two names unaddressable: `show key id_ed25519` and `adopt key id_ed25519` both return `not found` for a file plainly on disk, with no pointer to the canonical name. Attempting the canonical name instead fails from **both** verbs with `has 2 real locations; not a shape adopt can move` — shared wording, so an `edit` invocation blames `adopt`. Not blocking: `rm` on either copy resolves it immediately and is always safe, since the finding fires only on a shared fingerprint. The defect is that `check` names no remedy and the workaround error points at the wrong verb.
